## Reproduction and freeze caveats

- The invocation strings document CLI usage only; **none was executed**. Every listed result path and several one-shot lock files already exist, so the explicit `--execute` commands are not instructions to overwrite or rerun in place. A fresh run would require coordinator authorization and a new, registered output directory under the runner’s one-shot rules.
- In `specs/r4_trials.md`, the freeze section records D1, E1, J1, R1, and P1 SHA values. The variant table contains J1 and K1 entries, but the table’s legacy `specs/r4_prereg/...` paths are absent; the current files live under `specs/r6_prereg/`. The table has no variant row for D1, E1, R1, P1, or G1. K1’s prereg footer and trial metadata contain the same digest. G1's freeze is recorded at r4_trials.md line 92, matching its footer digest (coordinator correction).
- The freeze/footer SHA values above are canonical values recorded by the project workflow. Raw-file `Get-FileHash` values do not match those canonical values; this index does not silently substitute raw-byte hashes for the registered digests.
- A broad PowerShell filter used during path discovery briefly displayed existing trial-log result cells in the worker console. Those values were not used, copied, or included here; this index is a metadata inventory, not a blinded review. No result artifact contents or sealed holdout files were opened.

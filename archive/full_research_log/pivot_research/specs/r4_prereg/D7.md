## Hypothesis, sign, and horizon

When a Dow company publicly reports earnings, its market-adjusted price response predicts a same-direction return in Dow suppliers that previously named it in a public SEC filing. The event response is the customer's adjusted open-to-close return on a precisely defined event session, less the equal-weight Dow 30 (EW30) return over that same interval. A timestamp before 09:30 America/New_York (BMO) starts the event on that day's regular session; a timestamp at or after 09:30, including an after-market-close (AMC) release, starts the event on the next NYSE session. If the release time is unknown, start the event on the next NYSE session. In all cases the primary event shock uses adjusted open-to-close returns for the defined event session. The primary horizon is the supplier's next five-session open-to-close return, from the open of session `d+1` through the close of session `d+5`, where `d` is the customer's event-response session. This is a fixed short-horizon extrapolation, not a horizon directly established by the cited papers. D7 tests information diffusion along disclosed economic links; it does not directly measure buying pressure, signed order flow, or causal transmission.

The economic-link motivation is Cohen and Frazzini, “Economic Links and Predictable Returns,” *Journal of Finance* (2008), [DOI 10.1111/j.1540-6261.2008.01379.x](https://doi.org/10.1111/j.1540-6261.2008.01379.x), and Menzly and Ozbas, “Market Segmentation and Cross-predictability of Returns,” *Journal of Finance* (2010), [DOI 10.1111/j.1540-6261.2010.01578.x](https://doi.org/10.1111/j.1540-6261.2010.01578.x). Those papers motivate information diffusion over economic links; they do not establish this Dow event design or its five-session horizon.

## Earnings event and signal construction

Define a customer earnings event only from a verified SEC Form 8-K **Item 2.02** filing and its earnings release. Do not substitute earnings calendar dates, press reports, 10-K filing dates, or other 8-K items. The event table must include `customer_cik`, `accession_number`, `filing_date`, `acceptance_timestamp_et` and `acceptance_timestamp_utc` when available, `release_timestamp_et` when explicitly stated in the furnished exhibit (otherwise blank), the exhibit `source_url`, and the derived `response_session` `d`. Also record the normalized release and acceptance timestamps, `f`, `a`, and final `d` as defined below. The release timestamp is sourced from the furnished exhibit; the acceptance fields remain an audit trail and do not substitute for a missing release time.

Normalize EDGAR acceptance and any explicitly stated earnings-release timestamp to `America/New_York`. Let `a` be the first NYSE session whose 09:30 ET open is strictly later than the later known timestamp (release or acceptance); a timestamp exactly at 09:30 ET is not earlier than that open, so use the following session. Let `f` be the first NYSE session strictly after the 8-K filing date. The customer's event-response session is `d = later(a, f)`. If no explicit release timestamp is available, treat the filing-date anchor as date-only and set `d = f`; never use EDGAR acceptance as a substitute release time. A release during regular trading or after the close therefore uses the next session, and a release on a non-trading day uses the next NYSE session consistent with this rule. If `d` is unavailable in the development calendar, exclude the event and report it. The customer shock is the adjusted open-to-close return on `d`, after that full session has completed; use no part of a session that began before the known release. A customer-event/link pair is eligible only when both the event has reached `d` under this combined release/8-K filing clock and the relationship edge's `first_usable_session` is on or before `d`. Thus no edge filed later can be backdated to an earlier customer shock. Deduplicate multiple filings/amendments for one earnings release to one event; when multiple distinct customers have an event on the same response date, retain all their events and aggregate them as below.

Derive adjusted open as `raw_open × adjclose / raw_close`, matching the frozen D4/D5 price convention. For customer `c` on response session `d`, define one fixed EW30-excess event shock:

`u[c,d] = (adjusted_close[c,d] / adjusted_open[c,d] − 1) − EW30_open_to_close_return[d]`.

This is the sole primary event definition: **customer earnings-response EW30-excess return**. Do not replace it with CLV pressure, raw event return, a different benchmark, or an alternative event window. For each active Dow supplier `j` and response date `d`, define `S[j,d]` as the arithmetic mean of `u[c,d]` across event customers `c` with a `customer → j` edge that is publicly usable by the close of `d`. Require at least one such edge; otherwise `S[j,d]` is unavailable. Exclude the customer itself from the recipient cross-section and exclude a supplier with its own verified Item 2.02 response session on `d`. A date enters the mechanism series only if at least three suppliers have finite scores and valid next-five-session returns. Report distinct event customers, suppliers, links, response dates, and supplier-date observations.

## Primary mechanism test and placebos

For each eligible event-response date, calculate Spearman rank IC across the eligible Dow supplier recipients between `S[j,d]` and the supplier return `adjusted_close[j,d+5] / adjusted_open[j,d+1] − 1`. Use the date-wise IC series in chronological order and Newey–West standard errors with Bartlett lag 4. The primary mechanism gate requires **mean IC ≥ 0.0183**, **NW t ≥ 2.00**, and a positive sign. Report the number of usable event dates and all date-level ICs. This is a predictive test, not causal identification.

Run **500 within-industry link-shuffle draws**, using one NumPy `default_rng(20261110)` generator. For each event date, preserve the active customer events, shock values, supplier-side two-digit SIC group counts, number of event links per customer, and point-in-time Dow roster. Jointly reassign supplier endpoints within the same two-digit SIC as each observed supplier, with no self-edge, duplicate edge, or reuse of an endpoint within a customer's draw; preserve every customer's edge count and each date's supplier SIC counts. Use the latest dated SIC-panel code publicly usable by the response date. All eligible event dates must appear in every draw. If any date cannot be assigned or any of the 500 complete draws cannot be generated under these rules, mark the shuffle infeasible and end D7; do not drop dates or broaden the pool. For every draw, report the date-wise IC series and its mean. The observed primary mean IC must be greater than the 95th percentile of the 500 shuffled-link mean ICs, and its one-sided finite-sample randomization p-value `(1 + count(shuffle_mean >= observed_mean))/501` must be below 0.05. Also report the mean IC of the date-wise average across the 500 shuffle draws and a 90% Newey–West lag-4 confidence interval. Test that this mean is equivalent to zero within the fixed materiality band [−0.0183, +0.0183] using a two one-sided test (TOST); it passes only if both one-sided tests reject at 5% (equivalently, the 90% confidence interval lies wholly inside the band). The former `|NW t|<2` rule may be reported as a diagnostic, not as evidence of no effect.

Use one fixed timing placebo: move each actual event-response date exactly **20 trading sessions later** on the Dow market calendar, retain its already-public shock, and freeze each event's original response-date link set. Shift only the shock date: do not add links first disclosed after the original event. Exclude events whose shifted date or five-session outcome window is outside the development period, and report the excluded count. Calculate the shifted date-wise IC series with the same supplier cross-section and five-session return formula; report the mean and 90% Newey–West lag-4 confidence interval. Test equivalence to zero within [−0.0183, +0.0183] by TOST; it passes only if both one-sided tests reject at 5%. The former `|NW t|<2` rule may be reported as a diagnostic, not as evidence of no effect. This is one deterministic control, not 500 random draws. Report all primary and placebo results whether or not the primary passes. A failed primary or placebo gate ends D7; no portfolio follows.

## Portfolio, cost cap, and inference

Only after the primary and both placebo gates pass, form a portfolio on the fixed Dow market calendar every fifth trading session, starting on the first scheduled formation date with a valid signal. At formation date `t`, form each supplier score as the arithmetic mean of its registered event shocks from response sessions `t−4` through `t`, using only links already public by the close of each response session. Select the five suppliers with the highest finite scores, equal-weight long, and execute at the next session's open; hold until the following weekly formation. Require at least five finite supplier scores. When fewer than five are available, hold EW30 for that rebalance and report the date as lacking a D7 position; do not carry a stale D7 ranking. Formation active share is 83.3% when all 30 names are eligible, satisfying the ≥50% active-share requirement.

Charge **0.05% per dollar traded per side**, including buys and sells. Cap total traded notional, including buys and sells, at **0.50 NAV per rebalance** using the harness actual-trade convention; report uncapped requested turnover, capped executed turnover, realized costs, and the number of cap-binding dates. Compare gross and net returns with the point-in-time EW30 benchmark over identical dates. Portfolio passage requires positive net excess return, net Sharpe above EW30, gross active edge at least four times realized costs, average turnover ≤0.50 NAV per rebalance, and the one-sided 10-session circular block-bootstrap net-excess p-value below 0.05 after the full goal-wide Holm adjustment. Use 5,000 bootstrap draws, block length 10 sessions, and seed `20261110`. Report active share, annualized return, Sharpe, maximum drawdown, turnover, total costs, and DSR with `trial_count=30`. If the cap or active-share gate fails, report the failure; do not change the formation rule.
